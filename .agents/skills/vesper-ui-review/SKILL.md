# Vesper UI Review

## Read first
- `docs/art/ART_DIRECTION.md`
- `docs/art/UI_REFERENCE.md`
- `docs/art/ASSET_MANIFEST.md`
- `docs/feedback/REJECTED_PATTERNS.md`

## Workflow
1. Identify the UI state: narrative, exploration, conversation, evidence, ritual, inventory or Grimoire.
2. Compare hierarchy, density, portrait scale and typography to Vesper principles — not pixel-perfect NINAH copying.
3. Prefer removing UI before adding decoration.
4. Check that the background remains visually important.
5. Check dialogue geometry consistency.
6. Check that period/diegetic screens do not drift to cyberpunk/dashboard styling.
7. Verify any new asset provenance and manifest entry.
8. After implementation, test at desktop and narrow viewport.

## Reject immediately
- card-in-card SaaS layout;
- thin generic option typography;
- unnecessary borders everywhere;
- technical metadata visible to player;
- reference screenshots promoted directly to production.
